# 部署指南(本机 / 可迁移)

面向将来迁移到独立服务器(或另一台机器)的本地部署文档。当前演示环境为 **本机进程式部署**(非 Docker),端口规划:Gateway 后端 `8001`、前端 `3000`。

## 1. 前置条件

- Python 3.12+ 与 `uv`(backend 用,`cd backend && uv sync`)
- Node.js 22+(frontend 用,`cd frontend && pnpm install`)
- 网络可访问智谱 GLM-OCR 与 DeepSeek HTTPS 接口(如本机走代理,确保两 API 域名可达)

## 2. 环境变量(必配:backend/.env)

| 变量 | 用途 | 必填 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 教师 Agent 模型(DeepSeek Anthropic Messages API) | 是 |
| `TC_LLM_API_KEY` / `TC_LLM_API_BASE` / `TC_LLM_MODEL` | 批改流水线 LLM(与 Agent 同模型) | 是 |
| `TC_OCR_API_KEY` / `TC_OCR_MODEL` | 智谱 GLM-OCR(题目/手写识别) | 是 |
| `TC_OSS_ACCESS_KEY_ID` / `TC_OSS_ACCESS_KEY_SECRET` / `TC_OSS_BUCKET` / `TC_OSS_ENDPOINT` | 阿里云 OSS(图片上传与 OCR 公网 URL) | 否(缺失时上传功能报 `UPLOAD_CONFIG_MISSING`,其余可用) |

> `.env.example` 提供键名模板;`.env` 已被 `.gitignore` 忽略,严禁提交。

## 3. 一键部署

```bash
cd AI-Teacher-Copilot
./scripts/deploy-local.sh --seed      # 首次部署(仅初始化双角色账号,业务数据使用现有数据库)
./scripts/deploy-local.sh             # 日常启动(数据已就绪)
./scripts/deploy-local.sh --rebuild   # 前端代码更新后强制重建
./scripts/deploy-local.sh --stop      # 停止
```

脚本动作:env 校验 → 停旧进程 → 启动 Gateway(`logs/gateway.log`)→ 可选 seed → 启动前端(`logs/frontend.log`)→ 健康检查输出。

## 7. 迁移到服务器(步骤要点)

1. 拷贝项目源码目录(排除 `node_modules/`、`.venv/`、`.next/`、`logs/`、`tc-data/`、`.deer-flow/` 等运行产物)。
2. 目标机执行前置安装:后端 `uv sync`;前端 `npm ci`。
3. 配置 `backend/.env`(密钥)+ 根目录 `config.yaml`(模型/工具/Agent 定义,已被 gitignore,从本机原样拷贝)。
4. 拷贝 `backend/.deer-flow/agents/teacher-copilot/`(自定义 Agent:SOUL.md + config.yaml)。
5. 首次启动:`./scripts/deploy-local.sh --seed`。
6. 如公网访问,建议前置 Nginx/HTTPS 并把 `GATEWAY_PORT`/`FRONTEND_PORT` 按需要调整(脚本支持环境变量覆盖)。

## 8. 常见问题

- **上传图片报 `UPLOAD_CONFIG_MISSING`** → 补全 `TC_OSS_*` 四个变量后重启后端。
- **聊天 403 `CSRF token missing`** → 前端必须使用 DeerFlow `fetcher`(自动注入 X-CSRF-Token),勿用裸 `fetch`。
- **批改慢/不输出** → 检查 `logs/gateway.log` 中的 LLM/OCR 请求日志与网络代理。
