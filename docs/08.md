# AI Teacher Copilot：08 评测体系设计

## 1. 评测目标

本项目的评测不只判断“最终回答好不好”，而是覆盖从学生批改到 Teacher Agent 的完整链路，并能够在失败后定位问题根因。

整体采用三阶段体系：

```text
Agent / Workflow 执行（智能体 / 工作流执行）
        ↓
Judge 评判（裁判评判）
        ↓
失败 Case 定位（失败用例定位）
```

每个评测 Case 统一保留：

```text
问题
+
Gold / 标准事实（标准答案 / 标准事实）
+
实际输出
+
完整 Trace（完整执行轨迹）
```

最终形成：

```text
固定评测集
↓
重复执行
↓
完整 Trace（完整执行轨迹）
↓
程序规则 + LLM Judge（大模型裁判）
↓
通过率 / 质量 / 稳定性
↓
失败 Case（失败用例）自动诊断
↓
定位第一次出错的位置
```

评测分为两层：

```text
第一层：Grading Evaluation（批改评测）
确保学生侧批改事实本身可靠

第二层：Teacher Agent Evaluation（教师智能体评测）
确保 Teacher Agent（教师智能体）正确使用业务事实完成教师任务
```

两层必须分开评测，避免上游批改错误被错误归因到 Teacher Agent。

---

# 2. 整体评测架构

```text
                Evaluation Dataset（评测数据集）
                       │
       ┌───────────────┴──────────────┐
       ↓                              ↓
Grading Benchmark（批改评测集）   Teacher Agent Benchmark（教师智能体评测集）
学生批改评测                    教师 Agent 评测
       │                              │
       ↓                              ↓
Grading Workflow（批改工作流）   Teacher Lead Agent（教师主智能体）
       │                              │
       └──────────────┬───────────────┘
                      ↓
                    Trace（执行轨迹）
                      ↓
                   Judge（裁判）
                      ↓
       ┌──────────────┴──────────────┐
       ↓                             ↓
   Metrics（评测指标）           Failed Cases（失败用例）
                                     ↓
                              Diagnosis Agent（诊断智能体）
                                     ↓
                              Root Cause（根因）
```

核心原则：

```text
最终结果
= 衡量做得对不对

Trace（执行轨迹）
= 解释错在哪里
```

## 3.1 Math Benchmark（数学评测集）

数学每个 Case 保存：

```jsonc
{
  "case_id": "math_001",              // case_id（评测用例 ID）
  "question": "...",                  // question（题目）
  "student_answer": "...",            // student_answer（学生作答）
  "gold": {                            // gold（人工标准答案）
    "difficulty": "medium",            // difficulty（题目难度）
    "correct": false,                  // correct（是否正确）
    "score": 6,                        // score（总得分）
    "step_scores": [],                 // step_scores（过程分 / 分步得分）
    "error_types": [],                 // error_types（错误类型）
    "knowledge_points": []             // knowledge_points（知识点）
  }
}
```

Gold 由人工确认后冻结。

数学评测指标：

```text
Correctness Accuracy（对错判断准确率）
Score MAE（总分平均绝对误差）
Step Score MAE（过程分平均绝对误差）
Error Type F1（错误类型 F1）
Knowledge Point F1（知识点识别 F1）
Difficulty Accuracy（难度识别准确率）
Strong Model Upgrade Rate（强模型升级比例）
Average Latency（平均延迟）
Average Cost（平均成本）
```

这些指标全部由程序直接计算，不使用 LLM Judge。

### 数学模型路由重点评测

当前 Workflow：

```text
Qwen 小模型判断难度
↓
easy / medium（简单 / 中等）
→ 小模型继续批改

hard（困难）
→ Strong Model Fallback（强模型兜底）
```

重点验证：

```text
Routing Accuracy（路由准确率）
Strong Model Upgrade Rate（强模型升级比例）
Accuracy Change（准确率变化）
Latency Change（延迟变化）
Cost Change（成本变化）
```

## 3.2 English Essay Benchmark（英语作文评测集）

英语作文每个 Case 保存：

```jsonc
{
  "case_id": "essay_001",             // case_id（评测用例 ID）
  "question": "...",                  // question（作文题目）
  "essay": "...",                     // essay（学生作文）
  "rubric": {},                        // rubric（评分标准）
  "gold": {                            // gold（人工标准评分）
    "total_score": 16,                 // total_score（总分）
    "content": 4,                      // content（内容）
    "organization": 4,                 // organization（组织结构）
    "grammar": 3,                      // grammar（语法）
    "vocabulary": 5                    // vocabulary（词汇）
  }
}
```

其中评分维度为：

```text
content（内容）
organization（组织结构）
grammar（语法）
vocabulary（词汇）
```

英语作文当前 Workflow：

```text
作文原文 + Rubric（评分标准）
        ↓
Evidence Agent（评分证据提取智能体）
        ↓
evidence.json（结构化评分证据）
        ↓
Scoring Agent（评分智能体）
        ↓
GradingResult（最终批改结果）
```

### Evidence Agent（评分证据提取智能体）指标

```text
Evidence Coverage（证据覆盖率）
Evidence Correctness（证据正确率）
Unsupported Evidence Rate（无依据证据率）
```

### Scoring Agent（评分智能体）指标

```text
Total Score MAE（总分平均绝对误差）
Dimension Score MAE（评分维度平均绝对误差）
Evidence Grounding（证据支撑度）
Feedback Quality（反馈质量）
```

其中：

```text
Score Deviation（分数偏差）
→ 程序直接计算

Evidence Grounding（证据支撑度） / Feedback Quality（反馈质量）
→ LLM Judge（大模型裁判）按 Rubric（评分标准）评分
```

# 4. Teacher Agent Benchmark

Teacher Agent Benchmark 固定为 100 个 Case，并直接按照当前业务复杂度 L1–L7 划分。

| Level | 场景 | Case 数 |
|---|---|---:|
| L1 | Direct Tool | 20 |
| L2 | Single Skill | 15 |
| L3 | Adaptive Multi-Tool | 15 |
| L4 | Skill + Tool | 15 |
| L5 | Multi-Skill / Single-Agent | 15 |
| L6 | Parallel Sub-Agents | 10 |
| L7 | Reviewer Agent | 10 |
| | 总计 | 100 |

L1–L7 不再只是执行架构，同时作为 Teacher Agent Benchmark 的正式分类体系。

---

## 4.1 L1 Direct Tool

目标：验证 Teacher Lead Agent 对明确事实 / 对象查询能否直接选择正确 Tool。

评测内容：

```text
Tool Selection Accuracy（工具选择准确率）
Argument Generation Accuracy（参数生成准确率）
Tool Execution Success Rate（工具执行成功率）
Unnecessary Tool Call Rate（不必要工具调用率）
```

Case Gold 需要明确：

```text
expected_level（期望执行层级）
expected_tools（期望调用工具）
forbidden_tools（禁止调用工具）
```

---

## 4.2 L2 Single Skill

目标：验证已有标准教学任务能否正确路由到对应 Skill，并完整执行 Skill SOP。

评测内容：

```text
Skill Routing Accuracy（技能路由准确率）
Required Tool Coverage（必需工具覆盖率）
Tool Sequence Correctness（工具调用顺序正确率）
Evidence Grounding Rate（事实证据支撑率）
Task Completion Rate（任务完成率）
```

---

## 4.3 L3 Adaptive Multi-Tool

目标：验证没有匹配 Skill 时，Teacher Lead Agent 是否能够根据任务和中间结果自主组合多个 Tool。

评测内容：

```text
Required Tool Coverage（必需工具覆盖率）
Unnecessary Tool Call Rate（不必要工具调用率）
Adaptive Decision Correctness（自适应决策正确率）
Argument Generation Accuracy（参数生成准确率）
Task Completion Rate（任务完成率）
```

重点检查：

```text
Required Tool Continuation（是否根据中间结果继续调用必要工具）
Premature Stop（是否提前停止导致证据不足）
Irrelevant Tool Call（是否调用无关工具）
```

---

## 4.4 L4 Skill + Tool

目标：验证一个 Skill 完成主体任务后，Teacher Lead Agent 能否继续调用额外 Tool 完成剩余需求。

评测内容：

```text
Skill Routing Accuracy（技能路由准确率）
Tool Sequence Correctness（工具调用顺序正确率）
Intermediate Result Usage（中间结果使用正确性）
Additional Tool Correctness（额外工具调用正确性）
Task Completion Rate（任务完成率）
```

---

## 4.5 L5 Multi-Skill / Single-Agent

目标：验证多个串行教学任务能否由 Teacher Lead Agent 通过 Multi-Skill 完成，并且不会无意义升级 Multi-Agent。

重点指标：

```text
Multi-Skill Routing Accuracy（多技能路由准确率）
Tool / Skill Sequence Correctness（工具 / 技能执行顺序正确率）
Intermediate Result Usage（中间结果使用正确性）
Task Completion Rate（任务完成率）
Unnecessary Multi-Agent Rate（不必要多智能体升级率）
```

其中：

```text
Unnecessary Multi-Agent Rate（不必要多智能体升级率）
=
本应由 L1-L5 Single-Agent（单智能体）完成
却启动 Sub-Agent（子智能体）的运行次数
÷
所有 L1-L5 运行次数
```

这是 Single-Agent First 原则的核心量化指标。

---

## 4.6 L6 Parallel Sub-Agents

目标：验证班级级批量诊断、批量练习生成等场景下，Teacher Lead Agent 能否正确 Fan-out / Fan-in。

评测内容：

```text
Sub-Agent Delegation Accuracy（子智能体委派准确率）
Fan-out Correctness（并行扇出正确率）
Fan-in Completeness（结果汇总完整率）
Unnecessary Agent Count（不必要智能体数量）
Parallel Speedup（并行加速比）
Task Completion Rate（任务完成率）
```

执行行为要求：

```text
读取 Class-level Facts（班级整体事实）
↓
筛选 Attention Students / Task Scope（重点学生 / 任务范围）
↓
Fan-out（并行扇出）
```

禁止：

```text
未筛选 Business Objects（业务对象）
↓
直接对全班机械启动大量 Agent（智能体）
```

---

## 4.7 L7 Reviewer Agent

目标：验证 Reviewer 只在大型高价值教学方案中按需启动。

评测内容：

```text
Reviewer Trigger Precision（审核智能体触发精确率）
Reviewer Trigger Recall（审核智能体触发召回率）
Reviewer Correction Rate（审核纠错率）
Unnecessary Review Rate（不必要审核率）
```

Reviewer 不只评是否执行，还要评：

```text
Required Review Trigger（该启动时是否启动）
Unnecessary Review Avoidance（不该启动时是否保持关闭）
Correction Benefit（发现错误后是否真正产生纠错收益）
```

# 5. Evaluation Dataset 与 Snapshot

Teacher Agent 使用独立冻结评测数据库：

```text
teacher_eval_v1（教师智能体评测数据快照 v1）
```

其中包含固定：

```text
Teacher（教师）
Student（学生）
Class（班级）
Homework（作业）
Question（题目）
Submission（学生提交）
GradingResult（批改结果）
Student Profile（学生画像）
Class Profile（班级画像）
Homework Analysis（作业分析，可重算事实）
Question Analysis（题目分析，可重算事实）
```

构建流程：

```text
构造 / 导入 Evaluation Data（评测业务数据）
↓
人工校验
↓
生成 Gold Facts（标准事实）
↓
冻结 teacher_eval_v1（教师智能体评测数据快照 v1）
↓
所有 Agent Version（智能体版本）使用相同数据
```

离线 Benchmark 不直接依赖持续变化的开发库或生产库。

固定 Snapshot 的目的：

```text
同一个 Case（评测用例）
在任何 Agent Version（智能体版本）下
都面对完全相同的 Business Facts（业务事实）
```

否则底层数据变化后，Gold 会失效，无法进行稳定版本对比。

# 6. Teacher Eval Case Schema

Teacher Agent 每个 Case 固定保存：

```jsonc
{
  "case_id": "teacher_l5_001",         // case_id（评测用例 ID）
  "level": "L5",                       // level（期望业务复杂度层级）
  "query": "分析这次作业的问题，然后根据班级情况生成分层练习。", // query（用户问题）
  "snapshot_id": "teacher_eval_v1",    // snapshot_id（评测数据快照 ID）
  "expected": {                         // expected（期望执行行为）
    "execution_level": "L5",           // execution_level（期望执行层级）
    "skills": [                         // skills（期望调用技能）
      "homework-review",
      "differentiated-practice"
    ],
    "required_tools": [                 // required_tools（必须调用工具）
      "get_homework_analysis",
      "get_question_analysis",
      "get_class_profile",
      "list_class_students",
      "get_student_profile",
      "search_question_bank"
    ],
    "forbidden_tools": [],              // forbidden_tools（禁止调用工具）
    "required_subagents": [],           // required_subagents（必须启动的子智能体）
    "forbidden_behavior": [             // forbidden_behavior（禁止行为）
      "spawn_sub_agent",
      "invoke_reviewer"
    ]
  },
  "gold_facts": {                       // gold_facts（标准业务事实）
    "weak_points": [],                  // weak_points（薄弱知识点）
    "attention_students": [],           // attention_students（重点关注学生）
    "common_errors": []                 // common_errors（共性错误）
  }
}
```

Gold 不保存固定自然语言回答，而保存：

```text
Execution Level（正确执行层级）
Tool / Skill（正确工具 / 技能）
Required Business Facts（必须读取的业务事实）
Gold Facts Coverage（最终答案必须覆盖的标准事实）
Forbidden Behavior（禁止行为）
```

自然语言表达允许不同，只要求业务事实和执行行为正确。

# 7. 多次运行与稳定性评测

Teacher Agent 每个 Case 默认独立运行 5 次。

```text
100 Cases（100 个评测用例）
×
5 Runs（每个用例运行 5 次）
=
500 次完整 Teacher Agent Run（教师智能体运行）
```

单个 Case：

```text
Run 1 PASS（第 1 次运行：通过）
Run 2 PASS（第 2 次运行：通过）
Run 3 FAIL（第 3 次运行：失败）
Run 4 PASS（第 4 次运行：通过）
Run 5 PASS（第 5 次运行：通过）

Case Pass Rate（单用例通过率）
= 4 / 5
= 80%
```

多次运行用于区分：

```text
5 / 5（5 次全部通过）
→ 稳定正确

0 / 5（5 次全部失败）
→ 稳定失败，通常存在明确能力或实现问题

2 / 5、3 / 5、4 / 5（部分通过）
→ 具备能力但不稳定
→ 优先分析
```

对于时对时错的 Case，直接对比成功 Run 和失败 Run 的 Trace，定位执行差异。

最终总体指标固定为：

```text
Pass Rate（平均通过率）
Average Quality Score（平均质量分）
All-Pass Rate（全对率 / 稳定通过率）
```

其中：

```text
All-Pass Rate（全对率）
=
5 / 5 全部成功的 Case（评测用例）数
÷
总 Case（评测用例）数
```

# 8. Trace 设计

Trace 是 Agent 评测的核心基础设施。

只保存最终回答不够，必须保存 Teacher Agent 从输入到最终结果的完整执行过程。

统一建立：

```text
agent_trace（智能体执行轨迹表）
```

字段：

| 字段 | 含义 |
|---|---|
| `id` | Trace ID |
| `eval_run_id` | 所属评测 Run |
| `case_id` | Benchmark Case |
| `session_id` | 一次 Agent Session |
| `conversation_id` | 会话 ID |
| `round` | 第几轮 |
| `agent_name` | Lead / Diagnosis / Practice / Reviewer |
| `agent_instance_id` | Agent 实例 |
| `parent_agent_instance_id` | 父 Agent |
| `step_type` | 当前执行类型 |
| `input_data` | 完整模型入参 |
| `output_data` | 完整模型输出 |
| `tool_name` | Tool 名称 |
| `tool_arguments` | Tool 参数 |
| `tool_result` | Tool 返回 |
| `skill_name` | 当前 Skill |
| `latency_ms` | 延迟 |
| `input_tokens` | 输入 Token |
| `output_tokens` | 输出 Token |
| `cost` | 调用成本 |
| `status` | success / error |
| `created_at` | 时间 |

`step_type` 固定为：

```text
LLM（大模型调用）
TOOL（工具调用）
SKILL_START（技能开始）
SKILL_END（技能结束）
SUB_AGENT_START（子智能体开始）
SUB_AGENT_END（子智能体结束）
MEMORY_READ（读取记忆）
MEMORY_WRITE（写入记忆）
FINAL（最终回答）
```

每次和 LLM 的完整输入、完整输出都保留。

Tool Call 同样保留原始结构：

```jsonc
{
  "tool_calls": [                      // tool_calls（工具调用列表）
    {
      "name": "get_student_profile",   // name（工具名称：查询学生画像）
      "arguments": {                   // arguments（工具参数）
        "student_id": "stu_001",       // student_id（学生 ID）
        "subject": "math"              // subject（学科：数学）
      }
    }
  ]
}
```

Trace 后续承担：

```text
Process Evaluation（执行过程评测）
Failure Diagnosis（失败定位）
Success / Failure Run Comparison（成功 / 失败运行对比）
Cost / Latency Statistics（成本 / 延迟统计）
Multi-Agent Analysis（多智能体分析）
```

# 9. Process Evaluation

一次 Teacher Agent Run 不全部交给 LLM Judge。

可以确定判断的执行行为全部由程序根据 Trace 自动计算。

自动检查：

```text
Execution Level Correctness（执行层级是否正确）

Tool Selection Correctness（工具选择是否正确）

Argument Correctness（参数是否正确）

Required Tool Coverage（必需工具是否全部调用）

Forbidden Tool Check（是否调用禁止工具）

Skill Correctness（技能是否正确）

Tool / Skill Sequence Correctness（工具 / 技能顺序是否满足依赖关系）

Unnecessary Sub-Agent Check（是否错误启动子智能体）

Sub-Agent Type Correctness（子智能体类型是否正确）

Fan-out Correctness（并行扇出是否符合业务范围）

Fan-in Completeness（结果汇总是否完整）

Reviewer Trigger Correctness（审核智能体是否正确触发）

Memory Fact-source Check（记忆是否被错误当成业务事实源）
```

形成：

```text
Process Check（执行过程检查）
PASS / FAIL（通过 / 失败）
```

Tool / Skill / Multi-Agent 不再建设相互独立的评测系统，而统一通过 Teacher Agent Trace 自动计算不同能力指标。

# 10. LLM-as-Judge

Teacher Agent 最终输出是自然语言，不使用字符串完全匹配。

Judge 只负责最终回答质量评判，不替代 Process Evaluation。

固定四个 Rubric 维度：

| 维度 | 权重 | 评测内容 |
|---|---:|---|
| Factual Grounding | 40% | 业务事实是否正确、是否有事实支撑、是否编造 |
| Completeness | 25% | 用户要求的主要任务是否完整覆盖 |
| Relevance | 15% | 是否围绕教师请求回答、是否存在大量无关内容 |
| Analysis / Teaching Quality | 20% | 分析、诊断和教学建议是否合理 |

Judge 每个维度只能输出：

```text
0（最低档）
1（严重不足）
2（明显不足）
3（基本可用）
4（良好）
5（优秀）
```

不允许直接自由打 83、87、91 等连续分。

总质量分由程序计算：

```text
Quality Score（质量分）
=
Factual Grounding（事实支撑度） × 0.40
+
Completeness（完整性） × 0.25
+
Relevance（相关性） × 0.15
+
Analysis / Teaching Quality（分析 / 教学质量） × 0.20
```

---

## 10.1 Factual Grounding 档位

```text
5（优秀）
核心和次要业务事实全部正确，有明确事实依据，无编造

4（良好）
核心事实正确，仅存在轻微、不影响结论的问题

3（基本可用）
主体事实正确，但存在部分次要事实偏差或证据不足

2（明显不足）
存在明显事实错误，但仍有部分主要结论正确

1（严重不足）
核心业务事实错误

0（最低档）
明显编造不存在的学生、成绩、作业、知识点或其他业务事实
```

```text
Hallucinated Student（编造不存在的学生）

Hallucinated Score（编造成绩）

Hallucinated Homework（编造作业）

Hallucinated Knowledge Point（编造知识点事实）

Wrong Business Object（工具参数导致读取错误业务对象）

Memory as Fact Source（记忆被错误当成学生 / 班级业务事实源）
```

最终 PASS 条件：

```text
Process Check（执行过程检查） = PASS（通过）

且

Factual Grounding（事实支撑度） >= 4

且

Quality Score（质量分） >= 4.0
```

# 12. Diagnosis Agent

当一次 Run 判定为 FAIL，或一个 Case 无法达到 5 / 5 稳定通过时，进入失败诊断。

Diagnosis Agent 输入：

```text
User Query（用户问题）
+
Gold Expected（标准期望执行行为）
+
Gold Facts（标准业务事实）
+
Final Answer（最终回答）
+
完整 Trace（完整执行轨迹）
```

Diagnosis Agent 具备两个核心能力：

```text
Read-only Eval Snapshot Tool（读取指定评测快照的只读业务工具）

Run Trace Reader（读取指定运行完整执行轨迹）
```

诊断过程：

```text
读取 Trace（执行轨迹）
↓
从 Round 1（第 1 轮）开始逐步检查
↓
找到第一个与 Gold / Business Facts（标准答案 / 业务事实）冲突的位置
↓
必要时通过 Read-only Tool（只读工具）验证事实
↓
确认 Root Error（根源错误点）
↓
归因 Root Cause（根因类别）
```

核心原则：

```text
不是找 Final Error（最后表现出来的错误）

而是找 First Root Error（第一次真正出错的位置）
```

因为后续错误很可能只是前面错误的级联传播。

---

## 12.1 Root Cause 分类

一级分类固定为四类：

```text
MODEL（模型问题）
模型理解 / 推理 / 决策能力

PROMPT_SCHEMA（提示词 / Schema 问题）
System Prompt（系统提示词）
Tool Description（工具描述）
Skill SOP（技能标准流程）
Schema / Constraint Design（数据结构 / 约束设计）

TOOL_DATA（工具 / 数据问题）
Tool Implementation（工具实现）
SQL（数据库查询）
Redis（缓存）
Business Data（业务数据）
Profile Calculation（画像计算）

AGENT_FRAMEWORK（智能体框架问题）
Tool Orchestration（工具编排）
Context Passing（上下文传递）
Memory（记忆）
Sub-Agent（子智能体）
Fan-out / Fan-in（并行扇出 / 结果汇总）
Concurrency（并发）
Timeout（超时）
Result Passing（结果回传）
```

Diagnosis 最终统一输出：

```jsonc
{
  "root_error_round": 3,                       // root_error_round（第一次出错轮次）
  "root_error_agent": "TeacherLeadAgent",     // root_error_agent（发生根源错误的智能体）
  "category": "PROMPT_SCHEMA",                // category（根因一级分类）
  "component": "get_student_profile.description", // component（具体问题组件）
  "reason": "...",                            // reason（根因说明）
  "downstream_effect": "...",                 // downstream_effect（后续级联影响）
  "suggested_fix": "..."                      // suggested_fix（建议修复方式）
}
```

# 15. 最终评测闭环

完整评测体系最终固定为：

```text
400 Grading Cases（400 个批改评测用例）
+
100 Teacher Agent Cases（100 个教师智能体评测用例）
×
5 Runs（每个用例运行 5 次）

↓

Frozen Evaluation Snapshot（冻结评测数据快照）

↓

完整 Trace（完整执行轨迹）

↓

Deterministic Process Check（确定性执行过程检查）
+
LLM Judge（大模型裁判）

↓

Pass Rate（通过率）
Quality Score（质量分）
All-Pass Rate（全对率 / 稳定通过率）

↓

Failed / Unstable Cases（失败 / 不稳定用例）

↓

Diagnosis Agent（诊断智能体）

↓

First Root Error（第一次根源错误位置）
+
Four Root Cause Categories（四类根因）
```

一句话概括：

> **先通过独立 Grading Benchmark 保证批改事实可靠，再基于冻结业务快照构建覆盖 L1–L7 的 Teacher Agent Benchmark；每个 Case 多次运行并保存完整 Trace，确定性的 Tool / Skill / Multi-Agent 行为由程序自动评测，开放式最终回答由 LLM Judge 按固定 Rubric 评分；失败后由 Diagnosis Agent 沿 Trace 找到第一次真正出错的位置并完成根因归类，最终形成能够衡量能力、稳定性、成本收益并指导系统优化的完整评测闭环。**
