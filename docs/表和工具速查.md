# 表和工具速查

本文件记录当前实际落库的表结构、状态机与 Agent 工具参数，作为数据设计与评测设计的事实基准。

---

# 一、存储边界（先看这个，否则容易误读表的职责）

 SQLite/MySQL  = 唯一业务事实源（16 张表）  
 即时聚合      = Homework Analysis / Question Analysis 每次实时算，不落库
 画像          = Student/Class Profile 每次由 ProfileAlgorithmV1 从库重算，不做缓存

一个关键设计取向：**只保留"当前有效"状态，不建历史版本表**。同一个学生同一道题只有一条 submission；重新提交时删除旧的 ocr_result/grading_result（含诊断子表）再重算，而不是追加一条新记录。所以"批改历史"实际是靠 `grading_result` 里每题一条当前结果聚合出来的，不是流水账。

---

# 二、表设计（16 张，实际落库已确认）

## 2.1 基础组织（5 张）

|表|字段|含义 / 存什么|
|---|---|---|
|`teacher`|teacher_id (PK)|教师 ID，形如 `teacher_01`|
||name|教师姓名|
||created_at|创建时间|
|`student`|student_id (PK)|学生 ID，形如 `stu_003`|
||name|学生姓名|
||created_at|创建时间|
|`class`|class_id (PK)|班级 ID，形如 `class_03`|
||name|班级真实名称，如"八三班"|
||teacher_id|归属教师（字符串关联，非 FK 约束）|
||created_at|创建时间|
|`class_student`|class_id (PK)|班级 ID|
||student_id (PK)|学生 ID；与 class_id 组成复合主键，UNIQUE(class_id, student_id)|
||joined_at|入班时间|
|`account_link`|user_id (PK)|DeerFlow 登录用户的 uuid|
||biz_type|`teacher` / `student`|
||biz_id|对应业务 ID（teacher_01 / stu_003），UNIQUE(biz_type, biz_id)|

`account_link` 是 V2 上线后加的：登录态本身只知道 DeerFlow user_id，靠这张表换成可信的业务身份，避免让 LLM 或前端自报 teacher_id。

|表|字段|含义 / 存什么|
|---|---|---|
|`homework`|homework_id (PK)|作业 ID|
||name|作业名称|
||class_id|布置到哪个班|
||teacher_id|布置教师|

||status|`DRAFT` / `PUBLISHED`，发布后不可改题目|
||published_at|发布时间（发布时写入）|
||deadline|可选截止时间，**仅展示和"今天截止作业数"统计，不做逾期拦截**|
||created_at / updated_at|时间戳|

||question_type|`calculation` / `solution` / `essay`|
||difficulty|`easy` / `medium` / `hard` / NULL（英语固定 NULL）|
||content|题干文本|
||image_url|题目原图 URL（可选）|
||max_score|满分；英语作文固定 20|
||source_question_bank_item_id|来自题库哪道题，**仅追踪来源，不是实时引用**|
|`question_bank_item`|question_bank_item_id (PK)|题库题 ID|

||question_type / difficulty|题型 / 难度|
||content|题干|
||image_url|题目图|
||reference_answer|参考答案|
||tags|标签（字符串）|
||created_at / updated_at|时间戳|
|`question_bank_item_knowledge_point`|question_bank_item_id (PK)|题库题 ID|
||knowledge_point_key (PK)|标准 **level=2** 知识点 key，UNIQUE(题, 知识点)|

题库题加入作业时是**复制**成新 `question`（只记 source id），后续改题库不影响已布置的题。

## 2.3 提交与批改证据（5 张）

|表|字段|含义 / 存什么|
|---|---|---|
|`submission`|submission_id (PK)|提交 ID；**UNIQUE(student_id, question_id)** — 同一学生同一题只保留一条当前提交|
||student_id / question_id / homework_id|归属（homework_id 冗余，便于按作业聚合）|
||image_url|当前答案图片（OSS 公网 URL）|
||status|`PENDING` / `RUNNING` / `SUCCEEDED` / `FAILED`|
||current_stage|RUNNING 时的阶段：`QUEUED` / `OCR` / `PARSING` / `GRADING` / `ASSEMBLING_RESULT` / `COMPLETED`|
||error_code / error_message|失败原因|
||submitted_at / started_at / finished_at|提交 / 开始批改 / 结束时间|
||updated_at|更新时间|
|`ocr_result`|ocr_result_id (PK)|OCR 结果 ID；UNIQUE(submission_id)，一个提交最多一条|
||submission_id (FK)|关联提交|
||model|使用的 OCR 模型名|
||status|`SUCCEEDED` / `EMPTY`（识别跑通但没认出内容）|
||md_results|整图识别的 Markdown 文本|
||layout_details (JSON)|Block 数组：`index / label / content / bbox2d / width / height`，前端靠 bbox2d 在答案原图上画错误框|
||created_at|创建时间|
|`grading_result`|grading_result_id (PK)|批改结果 ID；UNIQUE(submission_id)，一个成功提交一条|
||submission_id (FK)|关联提交|
||subject / question_type / difficulty|批改时的题目属性（快照）|
||score_earned / score_max / score_rate|得分 / 满分 / 得分率|
||feedback (JSON)|`{summary, strengths[], improvements[]}`|
||math_detail (JSON)|数学专用：`{correct, final_answer, steps[]}`，可空|
||english_essay_detail (JSON)|英语作文专用：`{dimension_scores, language_errors[], evidence}`，可空|
||execution_meta (JSON)|`{route, models_used[]}`，记录走了哪条批改链路、用了哪些模型|
||created_at|创建时间|
|`grading_result_knowledge_point`|id (PK, 自增)|代理主键|
||grading_result_id|所属批改结果|
||knowledge_point_key|标准 level=2 知识点 key|
||name|字典补齐的展示名（冗余，便于直接展示）|
||raw_name|**本次模型诊断出的原始语义**，必须保存，用于证据回放|
||performance|`correct` / `partial` / `incorrect`|
||evidence|证据文本|
|`grading_result_error`|id (PK, 自增)|代理主键|
||grading_result_id|所属批改结果|
||error_code|标准 level=2 错误码|
||type_name|字典补齐的展示名|
||raw_type|本次模型诊断的原始错误类型|
||knowledge_point_key|关联知识点|
||description / evidence|错误描述 / 证据|

这里有个贯穿全库的设计原则：**统计只用标准 level=2 的 key/code，原始语义另存 raw_name/raw_type**。这样既能做确定性聚合，又不丢 LLM 每次诊断的真实表达。

## 2.4 标准分类字典（2 张）

|表|字段|含义 / 存什么|
|---|---|---|
|`knowledge_point`|key (PK)|知识点编码，如 `math.linear_equation.transposition`|
||name|标准展示名|
||subject|`math` / `english`|
||parent_key|level=2 时指向大类|
||level|1=大类，2=可落库小类|
||is_other|是否该大类的 OTHER 兜底（每个大类至少一个）|
|`error_type`|code (PK)|错误码，如 `SIGN_ERROR`|
||name / subject / parent_code / level / is_other|同上语义|

只有 level=2 的 key/code 允许进入 GradingResult、Profile、Analysis 和工具参数。

# 三、状态机（status / current_stage 字段的取值语义）

 homework.status:   DRAFT ──发布校验通过──▶ PUBLISHED（之后不可改题）  
 ​  
 submission.status: PENDING ──启动 Workflow──▶ RUNNING ──写入结果──▶ SUCCEEDED  
                                      └──不可恢复失败──▶ FAILED  
   PENDING/RUNNING 时重复提交 → HTTP 409  
   SUCCEEDED/FAILED 时重交 → 复用同一 submission_id：替换 image_url、删旧结果、重置为 PENDING/QUEUED

---

# 四、两个 JSON 列的内部结构（存的是结构化批改详情）

**math_detail**（数学）：`steps[]` 每步含 `step_index / description / evidence_block_ids / error_block_ids / status / earned_score / max_score / feedback`，且必须满足 Σmax_score = 总分、Σearned_score = 得分。错误框坐标前端按 `error_block_ids → layout_details.bbox2d → scale` 换算，API 不返回绝对坐标。

**english_essay_detail**（英语）：必须且只能四维 `content / organization / grammar / vocabulary`，每维 0–5 整数，总分 = 四维之和 = 20。

所有校验由后端确定性 Validator/Assembler 完成，非法输出不入库。

# 五、工具设计

## 5.1 统一约定

- **返回结构统一**：`{"success": true, "data": {...}}` / `{"success": false, "error": {"code", "message"}}`。全部错误码：

  |code|HTTP|含义|
  |---|---|---|
  |`INTERNAL_ERROR`|500|未归类的内部错误（兜底）|
  |`INVALID_ARGUMENT`|400|参数非法|
  |`PERMISSION_DENIED`|403|访问的对象不属于当前教师|
  |`TEACHER_NOT_FOUND`|404|教师不存在|
  |`STUDENT_NOT_FOUND`|404|学生不存在|
  |`CLASS_NOT_FOUND`|404|班级不存在|
  |`HOMEWORK_NOT_FOUND`|404|作业不存在|
  |`QUESTION_NOT_FOUND`|404|题目不存在|
  |`SUBMISSION_NOT_FOUND`|404|提交不存在|
  |`SUBMISSION_GRADING_IN_PROGRESS`|409|批改进行中，拒绝重复提交|
  |`GRADING_OUTPUT_INVALID`|422|批改输出未通过确定性契约校验|
  |`OCR_EMPTY_RESULT`|422|识别跑通但没认出任何内容|
  |`PROFILE_REBUILD_FAILED`|500|画像重建失败|
  |`DATA_SOURCE_ERROR`|500|数据源异常|
  |`MODEL_NOT_CONFIGURED`|503|模型密钥未配置|
  |`OCR_NOT_CONFIGURED`|503|识别密钥未配置|
    
- **权限不从参数来**：教师身份取 DeerFlow Runtime 可信身份，经 `TeacherPermissionService` 校验对象归属；**禁止让 LLM 在参数里自报 teacher_id**。
    
- **编码约定**：所有 `knowledge_point_key / error_code` 必须是标准 level=2；raw 语义只用于证据展示。
    
- **对象解析链路**：Context First → 对象发现工具 → 唯一匹配直接继续 → 歧义走 `ask_clarification`，绝不猜 ID。
    
- **注册方式**：`config.yaml` 里 `use: app.teacher_copilot.tools.<模块>:<函数>`，分 `teacher:data` / `teacher:resource` 两个 tool_group。
    
- **Tool 层保持轻**：只做「Schema 校验 → 取身份 → 权限校验 → 调 Service → 结构化返回」，SQL 和算法都在 Service 里，与业务 API 共享同一套 Service。
    

## 5.2 九个工具的参数

**1. `get_student_profile`** — 学生长期画像

|参数|必填|说明|
|---|---|---|
|student_id|是|学生唯一 ID|
|subject|是|`math` / `english`|
|sections|否|只返回指定模块，空=全量；可选 `overview` / `knowledge_points` / `weak_points` / `recurring_errors` / `difficulty_performance`|

返回 StudentProfile：`basic`(含 algorithm_version=profile_v1) + `overview`(attempt_count / avg_score_rate / recent_score_rate / trend) + 知识点掌握 + 薄弱点 + 重复错误 + 难度表现。由 ProfileAlgorithmV1 从库实时计算。

**2. `get_student_grading_history`** — 学生历史批改事实

|参数|必填|说明|
|---|---|---|
|student_id|是|学生唯一 ID|
|subject|否|学科过滤|
|knowledge_point_key|否|标准二级知识点过滤|
|error_code|否|标准二级错误类型过滤|
|homework_id|否|作业过滤|
|start_time / end_time|否|时间范围（ISO）|
|limit|否|默认 20|

返回 GradingResult 列表（含 key/code 与 raw 语义），给画像结论提供证据。

**3. `get_class_profile`** — 班级长期画像

|参数|必填|说明|
|---|---|---|
|class_id|是|班级唯一 ID|
|subject|是|学科|
|sections|否|可选 `overview` / `knowledge_points` / `weak_points` / `common_errors` / `attention_students`|

只回答班级长期学情，**不枚举名单**（那是 `list_class_students`）。

**4. `list_classes`** — 班级名称解析

|参数|必填|说明|
|---|---|---|
|keyword|否|班级名称关键字（如"八三班""三班"），空串返回当前教师全部班级|

返回 `[{class_id, name}]`。教师说"三班"时先调它把班名换成 class_id，不猜 ID。

**5. `list_class_students`** — 班级成员

|参数|必填|说明|
|---|---|---|
|class_id|是|班级唯一 ID|

返回 `[{student_id, name}]`，不计算成绩。

**6. `list_class_homeworks`** — 班级作业列表

|参数|必填|说明|
|---|---|---|
|class_id|是|班级唯一 ID|
|subject|否|学科过滤|
|start_time / end_time|否|时间范围（ISO）|
|limit|否|默认 20|

只返回已发布（`PUBLISHED`）作业，草稿不进入 Agent 视野；按发布时间过滤。返回 `[{homework_id, name, subject, published_at}]`，用于"本周复盘"这类先找 homework_id 的场景。

**7. `get_homework_analysis`** — 单次作业分析

|参数|必填|说明|
|---|---|---|
|homework_id|是|作业唯一 ID|
|class_id|是|班级唯一 ID（会校验作业确实属于该班）|
|sections|否|可选 `completion` / `performance` / `knowledge_points` / `questions` / `attention_students`|

返回 HomeworkAnalysis，由 AnalysisCalculationV1 即时聚合：completion(assigned/submitted/completion_rate)、performance(fully graded 人数 / 平均得分率 / 四档分布)、知识点表现、逐题统计、重点关注学生。

**8. `get_question_analysis`** — 单题下钻

|参数|必填|说明|
|---|---|---|
|homework_id|是|作业唯一 ID|
|class_id|是|班级唯一 ID|
|question_id|是|题目唯一 ID|

返回 `question_id / question_no / attempt_count / avg_score_rate / error_student_count / error_rate / common_errors`。题目不属于该作业或无有效作答时返回业务错误，**不会兜底成第一题**。

**9. `search_question_bank`** — 题库检索

|参数|必填|说明|
|---|---|---|
|subject|是|学科|
|knowledge_point_keys|是|标准二级知识点列表，**至少命中一个**；多个知识点分别找题要分别查询|
|difficulty|否|`easy` / `medium` / `hard`|
|question_type|否|`calculation` / `solution` / `essay`|
|grade|否|年级|
|count|否|默认 10|
|exclude_question_bank_item_ids|否|排除已选过的题|

只返回 `question_bank_item`，绝不混入已布置的 homework question。

## 5.3 配套的 3 个 Skill（工具权限边界）

|Skill|目标|allowed-tools|
|---|---|---|
|`student-diagnosis`|学生长期诊断，区分偶发错误与长期薄弱|get_student_profile, get_student_grading_history|
|`class-learning-analysis`|班级长期学情与优先级|get_class_profile, get_student_profile|
|`homework-review`|单次作业讲评，高错题下钻|get_homework_analysis, get_question_analysis, get_class_profile|

`allowed-tools` 是最大权限，不等于每次必须全调。`personalized-intervention` Skill 与其依赖的 `search_teaching_materials` 工具需要 RAG / 教学知识库，当前暂缓、未实现。
