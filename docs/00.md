# AI Teacher Copilot：项目设计推进路线

## 推进原则

项目按 **8 个步骤**推进，顺序保持稳定：先把业务事实和数据边界理清，再设计 Agent、Memory 与 Multi-Agent。

---

## 1. 确定业务边界和核心对象

先明确系统中的核心对象：学生、教师、班级、作业、题目、提交记录、批改结果、知识点、错误类型。

需要回答：

- 学生如何提交作业？
- 一次作业如何定义？
- 一道题如何定义？
- 批改结果属于哪一次提交？
- 教师后续需要查询哪些业务信息？

**产出：业务对象图 + 一次完整业务流程。**

---

## 2. 定义单次批改结果的数据结构

明确一题经过完整 Grading Workflow 后最终产出什么，例如：

```text
score
correct
knowledge_points
error_types
reason
feedback
model
difficulty
```

这一步决定后续能否稳定进行学生画像、班级学情分析和 Teacher Agent 查询。

**产出：统一 `GradingResult` Schema。**

---

## 3. 设计数据沉淀模型

明确哪些是原始事实，哪些是聚合结果：

```text
Grading Record      题目级事实
       ↓
Student Profile     学生知识画像
       ↓
Class Profile       班级学情画像
```

进一步设计：

- MySQL 表结构
- 数据更新机制
- 聚合方式
- 是否异步更新

**产出：数据库表设计 + 数据更新流程。**

---

## 4. 设计个性化评语和薄弱点分析

区分三个层次：

```text
本题评语
= 当前批改结果

长期个性化反馈
= 当前结果 + 学生历史

薄弱知识点
= 多次批改结果聚合
```

重点确定：

- mastery 如何计算
- 最近表现如何加权
- 趋势如何计算
- 多久更新一次
- 如何区分偶发错误和长期薄弱

**产出：学生画像算法。**

---

## 5. 设计 Teacher Agent 的 Tools

先定义 Teacher Agent 能够查询和调用的业务能力，例如：

```text
get_student_profile()
get_student_grading_history()
get_class_learning_summary()
get_high_error_questions()
get_weak_students()
search_textbook()
search_question_bank()
```

每个 Tool 需要明确：

- 输入参数
- 返回结构
- 数据来源
- 权限边界

**产出：Tool 清单 + 输入输出。**

---

## 6. 设计 Skills 和 Agent Memory

明确以下边界：

- 什么应该是 Skill？
- 什么应该进入 TencentDB Agent Memory？
- 什么必须保留在业务数据库中，不能进入 Memory 作为事实源？

例如：

```text
Skill
→ 班级学情分析 SOP
→ 学生诊断 SOP
→ 分层练习生成 SOP

Agent Memory
→ 教师偏好
→ 教学风格
→ 历史决策
→ 跨会话上下文
```

**产出：MySQL / Tool / Skill / Memory 边界表。**

---

## 7. 设计 Teacher Multi-Agent

在业务数据、Tools、Skills 和 Memory 边界明确之后，再决定 Teacher Copilot 如何拆分多个 Agent，例如：

```text
Supervisor
    ↓
├─ Learning Analyst
├─ Curriculum Agent
├─ Exercise Agent
└─ Reviewer（可选）
```

核心问题是：

> 为什么该任务需要多个专业 Agent 协作，而不是一次 LLM 调用？

需要明确每个 Agent：

- 职责
- 可使用的 Tools
- 可访问的数据
- 可使用的 Skills / Memory
- Agent 之间如何传递结果

**产出：Multi-Agent 架构图 + Agent 职责。**

---

## 8. 设计评测和工程实现

### 学生侧

```text
OCR
→ 小模型快速路径
→ 强模型 fallback
```

重点评测：

- OCR / 作答解析效果
- 批改准确率
- 过程分准确率
- 小模型路由准确率
- 强模型升级比例
- 成本与延迟

### 教师侧

```text
Agent Tool 调用正确率
学情分析准确性
Memory 命中率
Multi-Agent 成本 / 延迟
```

进一步评测 Teacher Agent 是否能够：

- 正确选择 Tool
- 正确读取学生与班级数据
- 基于事实进行学情分析
- 正确利用长期 Memory
- 在 Multi-Agent 协作中稳定完成复杂教学任务

**产出：最终技术架构 + 面试可讲的实验。**

---

## 整体依赖关系

```text
Step 1  业务边界与核心对象
   ↓
Step 2  GradingResult Schema
   ↓
Step 3  数据沉淀模型
   ↓
Step 4  个性化反馈与学生画像
   ↓
Step 5  Teacher Agent Tools
   ↓
Step 6  Skills + Agent Memory
   ↓
Step 7  Teacher Multi-Agent
   ↓
Step 8  评测与最终工程架构
```

核心原则：**先建立准确、可追溯的业务事实，再让 Agent 在这些事实之上进行查询、分析、规划和协作。**
